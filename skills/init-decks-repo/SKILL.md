# Create the user's decks repo

The user's decks are their data, so they live in a repo the user owns, not in this plugin. This skill creates it once and
records only the pointer.

## Config

```
CFG_DIR="${CLAUDE_USER_DATA:-${XDG_DATA_HOME:-$HOME/.local/share}/claude-plugins}/macro-deck"
CFG="$CFG_DIR/config.json"
```

`config.json`: `{"decks_repo": "<absolute local path>", "remote": "<owner/name>", "mcp_url": "http://127.0.0.1:8193/mcp"}`.
If it already exists and the path is a git repo, say so and stop. If the user already has a decks repo (new machine),
clone it, write `config.json` pointing at the clone, and stop.

## Steps

1. Ask (one question, with defaults): repo name (default `Macro-Deck-Profiles`), local parent folder (default
   `~/repos/`), GitHub owner (default: `gh api user -q .login`). Private by default: decks can name hosts, IPs and
   local endpoints.
2. Create and clone:
   ```bash
   gh repo create <owner>/<name> --private --description "My Macro Deck decks: specs and snapshots" --clone
   ```
   (run in the parent folder; if `gh` is unavailable, `git init` locally and tell the user to add a remote.)
3. Scaffold:
   ```
   README.md          what the repo is, how decks are built and restored (plugin macro-deck)
   CLAUDE.md          for agents: layout below, "edit decks/<slug>/deck.json, then build-deck; snapshots are generated"
   decks/             one folder per deck: deck.json (spec, hand/agent-edited), snapshot.json (generated by save-decks)
   hosts/             <hostname>.json: Macro Deck version, port, which decks are on that host, profile/folder ids
   .gitignore         *.token, *.env, .secrets*
   ```
   Spec format: see `build-deck` (`references/deck-spec.md`).
4. Commit `Initial decks repo` and push.
5. Write `config.json` (create `$CFG_DIR`), and report the repo URL and local path.

Never put tokens or secret values in the repo. Secret parameters in a spec are written as `{"$secret": "<label>"}` and set
through the MCP `set_secret` tool at build time.
